# 服务端口仅监听本机,访问需出示令牌(Jupyter 式)

gossh 默认只监听 `127.0.0.1`,启动时生成(或从 `~/.gossh/token` 加载)一个随机访问令牌,浏览器通过 `/?token=<t>` 打开页面;之后每个 `/api/*` 请求与 WebSocket 连接都必须出示令牌(常量时间比较),静态页面本身无需令牌。另有 `--ws-origin` 正则兜底阻止跨站 WebSocket。

理由:
- gossh 是 SSH **客户端**,本地进程持有私钥/密码;把服务暴露到局域网等于把全部 SSH 身份暴露给任何能到达端口的人。gotty 的默认(`0.0.0.0` + 允许写入)对"运行已选命令"的工具尚可辩护,对 gossh 不可接受。
- 仅本机监听 + 令牌:防局域网偷渡(其他设备连不上)、防恶意网页 CSRF(令牌不在浏览器 Cookie 中,跨站页面无法读取 URL 里的令牌以伪造请求)。
- Jupyter 式"打印带令牌的 URL"零配置成本,且令牌持久化到文件后重启不漂移,仍可被用户以 `--token` 显式替换。

代价:每次打开都要带令牌(或通过浏览器地址栏/配置文件固定);没有"零配置直接开"的体验,但对持有私钥的工具这是正确取舍。

备选:仅监听本机不带令牌(本地恶意进程本可读密钥文件,增益小但体验好——牺牲了防恶意网页/浏览器漏洞的纵深)、`0.0.0.0` 暴露靠 TLS 反向代理自加固(风险前置,已否决)。
